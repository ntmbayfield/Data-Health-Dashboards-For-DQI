Why the gate is segmented rather than a single tolerance
BLOCK IF  ANY segment variance > ±1%  — not  total variance > ±1%

A doctoral degree code added in AY25–26 was never added to the extract filter. Education came in 23.7% short.

What a whole-file tolerance would have missed

Aggregate variance was −2.0%, comfortably inside any sensible file-level threshold. The load would have passed clean and 66 doctoral graduates would have been silently absent from the alumni database — surfacing years later at a reunion mailing as a complaint rather than a data finding. Small segments cannot be defended by aggregate checks; the arithmetic hides them by design.

Why 1,791 of 4,102 graduates already existed

Student donors, event attendees, children on a household account, scholarship recipients. 44% of every incoming cohort is already in Salesforce. If matching is weak, the semiannual graduate import is simultaneously the largest single source of duplicate Contacts in the org — and because it runs twice a year, the duplicates arrive in two large batches nobody is watching for.

Tier C exists because both automatic options are wrong

Auto-creating a possible match produces hundreds of duplicates in one afternoon. Auto-merging produces a merged pair that takes three weeks to unwind and may be unrecoverable. Holding is the only safe third option, and it works only if someone owns the queue — the 143 held here have been open 81 days with no assignee, which is the actual finding.

The question this board answers is not "did the import succeed"

It is who graduated and did not arrive. The import reported success. 3,959 records processed, alumni constituency at 100%, no failures. Every conventional post-load report would call this a good cycle.

Why the gap must be computed against an external expectation

The 85 missing graduates were never in the extract, so they appear in no log, no error report and no row count — the pipeline cannot report on records it was never given. The only way to find them is to reconcile against the registrar's own count, by segment, from a source the extract does not control. This is the same structural problem as staleness on board 02: absence is not an event, so it has to be derived from an expectation. The process also runs twice a year, so nobody remembers it — the run-book gets the same attestation requirement as a mapping.

Board 03
D3

FERPA scope. Grades, courses and application data have no advancement use case and are readable across a five-unit org. Scope to directory plus degree and graduation only, and drop directory-suppressed students before load. Counsel decides.

BR-5

Build the student ID crosswalk before December. A unique External ID on Contact turns every future cycle into an upsert instead of a fresh fuzzy match. Zero of 3,959 loaded graduates carry one today. Retrofitting after another name-and-DOB cycle costs more than building it now.

BR-11

The gate blocks at segment level, not on the file total, and tier C holds need a named owner. The 143 held here have been open 81 days with no assignee.
